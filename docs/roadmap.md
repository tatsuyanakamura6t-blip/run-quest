## 2. 前提：XREAL Air の特徴

- **カメラが付いていない**。グラスは「メガネ型の外部ディスプレイ」なので、風景を読み取るには**スマホのカメラ**を使う。
- **USB-C ケーブルでスマホとつなぐと、スマホの画面がそのまま映る**（ミラーリング）。映像出力（DisplayPort Alt Mode）に対応したスマホが必要。USB-C の iPhone（15以降）も対応。
- **画面の黒い部分は透明に見える**。黒い背景に情報だけを描けば、現実の風景の上に情報が浮いて見える。
- 画面は**横長（16:9）**。グラス用の表示は横向きで作る。

→ 先生の方針どおり、**まずスマホのカメラ画面で完成させ、最後に表示だけをグラス向けに切り替える**。

## 3. 全体の構成

```
［スマホ］
  GPS ──────┐
  カメラ ────┼─→ ゲーム処理（距離・ペース・スコア・コイン・AIコーチ）─→ 画面描画 ─USB-C→ ［XREAL Air］
  （音声）←──┘
```

走る前に**距離か時間を入れると、今いる場所から戻ってくる周回コースを自動で作る**（先生のフィードバック）。
コースが決まっていると「スタートから◯m の地点」がわかるので、並走者（AIコーチ）の位置やコインを置く場所を決めやすくなる。

画面は3つのモードを切り替える。

| モード | 背景 | 使う場面 | 状態 |
| --- | --- | --- | --- |
| マップモード | 地図 | 走る前・走った後の確認 | できている |
| カメラモード | 背面カメラの映像 | スマホだけで遊ぶ／開発中の確認 | 次に作る |
| グラスモード | 真っ黒（＝透明に見える） | XREAL Air に映して走る | 12月に作る |

## 4. 技術選定

| 項目 | 使うもの | 理由 |
| --- | --- | --- |
| アプリの形 | **Webアプリのまま続ける**（GitHub Pages） | 今のコードを再利用できる。ミラーリングで映せるので、グラス専用アプリを作らなくてよい。iPhone と Android の両方で動く |
| 位置 | Geolocation API（＋カルマンフィルタ） | すでに実装・検証済み |
| コースづくり | 徒歩の経路検索（OSRM、routing.openstreetmap.de） | APIキーが要らないので、公開リポジトリでも安全 |
| カメラ | getUserMedia（背面カメラ） | ブラウザだけで使える |
| ゲーム画面 | HTML / Canvas を映像の上に重ねる | 作りやすく、見た目を変えやすい |
| 音声 | Web Speech API（読み上げ） | 画面を見なくても状況がわかる |
| 道の認識（挑戦） | MediaPipe（画像の領域分け） | ブラウザで動く。重ければ見送る |

**検討してやめたもの**：Unity ＋ XREAL SDK（グラスの向きに合わせて物を空間に固定できるが、学習に時間がかかり、Android 限定になる）。Webで最低ラインが完成し、時間が残れば検討する。

## 5. ゲームの設計

| 要素 | ルール（案） |
| --- | --- |
| スコア | 走った距離 × コンボ倍率 で増える |
| コンボ | 目標ペースの ±10% を保つと上がる（最大 ×5）。外れるとリセット |
| コイン | コース上に 100m ごとに置き、そこまで走ると獲得。GPSの距離で判定するので、正確な位置合わせがいらない |
| AIコーチ | 目標ペースでコース上を走る仮想ランナー。「◯m 前／後ろ」を表示し、音声でも伝える |
| 音声 | 1kmごとのペース、コイン獲得、AIコーチに抜かれた／抜いた、を読み上げる |

## 7. リスクと代わりの案

| リスク | 代わりの案 |
| --- | --- |
| 手元のスマホが映像出力に対応していない | 研究室の対応スマホを借りる／USB-C の iPhone を使う |
| 道の認識が重い・うまくいかない | コインを「画面の奥から近づいてくる」演出にする（距離だけで判定） |
| カメラと GPS を同時に使うと電池・発熱が厳しい | グラスモードではカメラを切る（グラスは透けて見えるので映像は不要） |
| 画面が消えると GPS が止まる | 画面スリープ防止（実装済み）／必要ならネイティブアプリ化を検討 |
| グラスをかけて走るのは危険 | 実走テストは人の少ない公園などで、付き添いありで行う。表示は視界の端にまとめる |
